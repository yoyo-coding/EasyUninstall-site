Safety by design

安全不是口号，是一行行代码

很多工具的「强力清洁」意味着粗暴删除。EasyUninstall 反其道而行：把删除的决定权，交还给软件自己的官方卸载程序。

我们绝不任何情况下都不会发生

  • 直接删除软件的安装目录、用户文件或注册表
  • 把卸载命令丢给 cmd.exe 或 PowerShell 执行
  • 用字符串拆分去「猜」可执行文件和参数

我们始终每一行代码都在遵守

  • 独立命令解析器验证每条卸载命令，拒绝 cmd / powershell / mshta / rundll32 / regsvr32 等危险宿主
  • MSI 仅接受 MsiExec.exe /X{GUID} 模式，并校验 GUID 格式
  • 命令有歧义时禁用卸载按钮，并向你说明原因
  • 卸载后重新扫描清单，确认结果才作数
  • 默认无需管理员权限，仅在卸载程序需要时按需提权
UninstallCommandParser — 实际校验逻辑示意
✓ 通过  "C:\Program Files\Yunjian\unins000.exe" /SILENT — 可执行文件真实存在
✗ 拒绝  C:\Windows\System32\cmd.exe /c del /f ... — 危险宿主：cmd.exe

Force uninstall

对付顽固软件，也留有护栏

当软件没有可验证的官方卸载器时，详情区会提供强制卸载选项——一个显式的、需要二次确认的高影响操作。

1

二次确认 + 提权

确认对话框明确警告副作用，随后请求管理员权限（UAC）。

2

结束进程树

强行结束该软件正在运行的全部进程，避免文件占用。

3

删除安装目录

仅删除该软件自己的安装目录，UI 与提权助手双重校验路径安全。

4

清理卸载项

仅删除该软件自己的卸载注册表项，绝不动其他软件的条目。

安全护栏

以下路径无论以任何理由，都会被拒绝执行：

C:\ 盘根 C:\Windows C:\Users C:\ProgramData WindowsApps 自身目录 浅路径

如实相告的副作用：共享组件、文件关联、开机启动项与服务不会被清理；共用目录的其他软件可能受影响。确认对话框会逐条写明。Store 应用不提供强制卸载，它们有专用的包管理机制。

FAQ

常见问题

EasyUninstall 会把软件「删干净」吗？
安全卸载模式下，EasyUninstall 调用软件自带的官方卸载程序完成清理，并重新扫描清单确认结果。它不做注册表深度扫描式的「暴力清洁」。对没有可验证卸载器的顽固软件，可使用带安全护栏的强制卸载；快捷方式、文件关联、开机项等残留清理已在路线图中。
为什么有的软件卸载按钮是灰色的？
说明该软件的卸载命令有歧义或无法验证——例如指向一个不存在的可执行文件，或尝试通过危险宿主执行。为避免运行来路不明的命令，按钮会被禁用，并告诉你原因。这正是安全设计在起作用。
需要管理员权限吗？
默认不需要。EasyUninstall 本身以普通权限运行，仅当卸载程序自身需要提权（触发 UAC），或你主动使用强制卸载时，才会请求管理员权限。
卸载完成后，怎么确认真的卸掉了？
启动卸载程序 ≠ 卸载成功。EasyUninstall 会在卸载后重新扫描软件清单，并将结果明确区分为：成功 / 失败 / 用户取消 / 结果未知，绝不模糊带过。
支持哪些系统？要装运行时吗？
支持 Windows 10 17763+ 与 Windows 11。自包含部署——应用本身运行无需安装 .NET 或任何其他依赖，MSIX 装完即用。
